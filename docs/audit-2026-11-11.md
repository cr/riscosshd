# Code audit, 2026-11-11

Full read of every source file, script, build file, patch and document at
commit 1eb1ce8 (4100 lines).  All items were addressed in the commit that
follows 1eb1ce8, except: item 10 (Ctrl-C as Escape) was verified by test
rather than changed, and item 26 turned out to be a misdiagnosis (elf2aif
never copied the debug info; the 1.3 MB is code, mostly libssh, mbedTLS
and UnixLib).

## Security and robustness

1. **No deadline for unauthenticated or idle sessions** (`src/server.c`).
   A client can connect and sit in key exchange or authentication for
   ever, and an authenticated session with no channel is never dropped.
   With `MAX_SESSIONS` 8, eight idle TCP connections lock everyone else
   out.  Add a per-session deadline: ~60 s to authenticate, and an idle
   timeout for sessions without a channel.
2. **An authorized key is full control of the machine.**  Any key in
   `authkeys` can run any `*command`, and the SFTP root is only a start
   directory: `/ADFS::4.$/` and every other filing system are reachable,
   including `!Boot`.  That is the right design for a single-user RISC OS
   box, but the README should say it in one sentence, and the user name
   being ignored belongs in the same sentence.
3. **TaskWindow output length is trusted** (`src/backend_taskwindow.c`,
   `tw_message`).  `block[5]` comes from another Wimp task and is used as
   a byte count into the 256-byte poll block.  Clamp it to
   `block[0] - 24` (at most 232).  Only a local task can exploit it, but
   the fix is one line.
4. **Blocking mode inside the event loop** (`src/backend_sftp.c`).  While
   SFTP owns a channel the whole session is blocking, so a reply that
   waits for window space nests `ssh_handle_packets` inside a callback.
   libssh's SFTP server was not written for re-entry; it has held up in
   tests, but a stall in one SFTP client also stalls every other session
   and the desktop.  Worth a comment now and a non-blocking rework later.
5. **Capture fallback runs commands in the server's own task**
   (`src/backend_exec.c`).  A command that never returns, or that calls
   `OS_Exit`, takes the server with it.  Documented in the README, but the
   quoted-command fallback makes it reachable from any client; consider
   refusing such commands instead of running them in-process.
6. During a key fetch (`src/wimp.c`, `keys_fetch`) the server loop does
   not run for up to the 15 s connect timeout plus the transfer, and
   `wimp_pump` swallows TaskWindow and DataLoad messages instead of
   routing them through `user_message`.  A TaskWindow child whose
   recorded Output message is not acknowledged kills itself, so a live
   shell session can die while someone uses Import.  Route reasons 17/18
   in `wimp_pump` through `user_message`.

## Correctness

7. **Duplicate keys are accepted** (`src/auth.c`, `auth_add_key_line`).
   Importing twice, or dropping the same file twice, appends the same key
   again.  Check `auth_key_allowed` first and report "already present".
8. **Key comments keep a leading space** (`src/auth.c`, `parse_line`).
   The comment token is taken with delimiters `\r\n` only, so it starts
   with the space after the base64.  Shows as a double space in the Keys
   window and in the rewritten `authkeys`.  Skip leading whitespace.
9. **Wrong port in the listen error** (`src/main.c`): `fatal("Cannot
   listen on port %s", "22")` prints 22 whatever `-p` said.
10. `Ctrl-C` is translated to byte 27 for the TaskWindow child
    (`tw_data`); whether the TaskWindow module treats an input 27 as an
    Escape condition was never verified.  Test it, or send
    `Message_TaskWindow_Morite` semantics via the documented route if it
    does nothing.
11. `queue_input` silently drops input beyond 4 KB while the child is not
    reading; log it once per session so a stuck child is diagnosable.
12. `wimp_init` can return -1 after `Wimp_Initialise` succeeded, and
    `main` then exits without `Wimp_CloseDown`; harmless in practice but
    untidy.  Call `wimp_shutdown` on that path.
13. `fstat` is still `process_unsupposed` in libssh's SFTP table.  Clients
    work around it, but an `fstat` handler on RISC OS is ten lines and
    would also remove the special-casing in the read handler.
14. `main.c` installs `ro_init_signals(on_quit)`, but in Wimp mode
    `on_quit` sets `main.c`'s `running`, which `wimp_run` never reads.
    Harmless; either drop it in Wimp mode or make the Wimp loop honour it.

## Dead code and obsolete complexity

15. Unused: `auth_describe()` (`auth.c`/`auth.h`), `ro_object_type()`
    (`riscos.c`/`riscos.h`), `ICON_ESG`/`ICON_SELECTED`/`ICON_DELETED`
    (`wimp.c`), `SESS_DEAD` and `listen_cb_noop` with its `(void)` cast
    (`server.c`), `#include <errno.h>` in `server.c`, `cols`/`rows`/`term`
    in `struct chan_ctx` (stored, never read), palette entries `G` and `D`
    in `tools/mksprites.py`.
16. `set_icon_text()` has `buf`/`size` parameters that every caller passes
    as `NULL, 0`.  Drop them.
17. `cb_exec_request` and `cb_shell_request` reset `c->backend = NULL`
    after a failed `start_backend`, which already does that.
18. `wimp_pump` duplicates the dispatch in `wimp_run`.  Factor a
    `dispatch(reason, block)` used by both (this also fixes item 6).
19. `struct wimp_window` sizes its icon array with
    `KI_COUNT > 16 ? KI_COUNT : 16`; name the maximum once.
20. `tools/build.sh` and `tools/ci-build.sh` are superseded by the
    Makefile but still referenced ten times (`CMakeLists.txt` comment,
    `tools/docker-env.sh`, `tools/rpcemu-install.sh`, `docs/toolchain.md`).
    Delete them and fix the references, or make them two-line wrappers
    around `make`.
21. `backend_shell.c` is now only the `-t` text-mode fallback.  Keep it if
    `-t` stays a supported debug mode; its header comment ("stopgap until
    the TaskWindow backend exists") is stale either way.

## Build system

22. **`tools/docker-env.sh` breaks Docker without Colima.**  It sets
    `DOCKER_HOST` to the Colima socket whenever the variable is unset,
    even when that socket does not exist, so on Docker Desktop or on a
    GitHub runner `docker info` fails and `make ENGINE=docker` cannot
    work.  Only set `DOCKER_HOST` when the Colima socket exists.  This
    means the committed CI workflow is currently broken.
23. CI cache key omits `deps/riscos-compat/**`, so a change there would
    reuse a stale libssh.
24. `find_path(... REQUIRED)` and `find_library(... REQUIRED)` in
    `CMakeLists.txt`: `REQUIRED` arrived in CMake 3.18, the container has
    3.16, and `cmake_minimum_required` says 3.12.  Today it only works
    because the libraries are always found.  Bump the minimum or check
    the results explicitly.
25. `.image-built` is a sentinel file: removing the image with the engine
    does not trigger `make image` again.  Minor; `make image` fixes it.
26. The AIF binary carries full debug info (1.3 MB).  `-s` at link time
    halves the package; UnixLib backtraces do not need the ELF symbols.

## Documentation

27. `README.md` is a layer cake of milestones: the intro still describes
    the line-mode prompt as the shell, "Installing and running" says the
    app opens a TaskWindow and that commands run synchronously in the
    server task, the "Sockets" bullet says the server runs in a
    TaskWindow, and the layout list lacks `backend_sftp.c`,
    `riscos_compat.c` and the headers.  Rewrite the intro and that section
    around the current behaviour.
28. `docs/toolchain.md`, "How dependencies are built", describes
    `tools/build.sh`/`ci-build.sh` and a workflow that "runs the same two
    scripts"; now it is the Makefile.
29. `docs/rpcemu.md`, "Getting the app into the emulator": mention
    `make install`.
30. `riscos/!SSHd/!Help,fff`: the menu line lacks Info..., the Keys
    section calls the button "Fetch" (it is "Import"), says the host key
    is at the bottom (it is at the top), and lists `-r` before `-p`.
31. `riscos/RiscPkg/Control`: the Description still says commands run
    through `OS_CLI`; it should mention SFTP and the TaskWindow.  More
    useful: `Depends: CryptRandom` makes PackMan install the entropy
    module automatically instead of `!Run` failing on a fresh machine.
32. Stale comments: `wimp.c` header lists the menu without Info...;
    `main.c` header and `usage()` synopsis omit `-r`; `tools/docker-env.sh`
    says "used by tools/build.sh"; `CMakeLists.txt` says "see
    tools/build.sh".

# Second pass (same day, after the fixes above)

All 23 items below were addressed in the commits that follow c9f3c33.
S16 was confirmed by test (12 of 120 piped lines lost: the module's key
buffer is 256 bytes and drops the rest) and fixed by pacing input a line
at a time against the child's echo; S23's memory measurement remains for
the user to take from the Task Manager under load.

Angles: flow control and memory growth, teardown and crash paths, SSH
protocol edge cases, SFTP semantics of libssh's default server, Wimp
protocol details, licensing and supply chain.  Two findings were confirmed
by test against the emulator, two by reading libssh's source; the rest by
reading ours.  An independent reviewer read the tree too; its findings
are merged here.

## High

- **S1. Blocking SFTP replies can deadlock the server and the desktop.**
  `src/backend_sftp.c` puts the session in blocking mode.  A reply written
  from inside the data callback that meets a zero channel window waits for
  a window update; but libssh (src/poll.c, `lock_cnt`) restricts a socket
  whose callback is running to write events only, so that update is never
  read.  Nothing polls the Wimp meanwhile.  Reachable with any client that
  pipelines more than the 2 MB window.  Fix: stay non-blocking, queue
  incoming bytes in the backend, and process SFTP packets from `poll()`
  only while the channel window can take the largest reply.
- **S2. SFTP overwrite keeps the old tail** (confirmed: 28 bytes over
  300000 left 300000).  libssh's `process_open` ignores `SSH_FXF_TRUNC`
  and `SSH_FXF_EXCL`.  Fix in the patch: map them to `O_TRUNC`/`O_EXCL`.
- **S3. No flow control toward TaskWindow children.**  `chan_output`
  grows without bound while a child outruns a slow or stopped client, and
  Output messages must be acknowledged or the child dies.  Fix: send
  `Message_TaskWindow_Suspend` above a high-water mark and `_Resume` below
  a low one, from `tw_poll`.
- **S4. Open SFTP files leak on teardown.**  `sftp_server_free` frees only
  the handle array (libssh src/sftp.c), never the `fd`/`DIR*` inside each
  handle.  A client that drops mid-transfer leaves the file open in the
  server task ("File open" for other apps, unflushed data).  Fix: patch in
  `sftp_server_close_handles()` and call it from `sftp_stop`.

## Medium

- **S5. Multiplexed connections break** (confirmed with ControlMaster: the
  master died 2 s after its first channel).  The session is destroyed
  after its channel closes.  Fix: keep the session, apply the 120 s
  no-channel idle deadline, allow a new channel; drop `close_deadline`.
  Also accept a new channel in the same poll as the old one's close.
- **S6. Control characters in an exec command cut the TaskWindow command
  line** (`\n` in the command ends the `*TaskWindow` line before `-task`).
  Fix: refuse commands containing bytes below 0x20 or 0x7f.
- **S7. A channel torn down before the child's Ego orphans the child.**
  `tw_stop` frees the state when `child == 0`; the later Ego matches
  nothing and the child lives on.  Fix: keep an `orphaned` state and send
  Morite when its Ego arrives.
- **S8. A child killed from the Task Manager never ends the channel** (no
  Morio).  Fix: register `Message_TaskCloseDown` (0x400C3) and match the
  dying task handle against children.
- **S9. Client-chosen SFTP read length is used unclamped** for `malloc`
  and the reply (libssh `process_read`).  Fix: clamp to 64 KB in the patch.
- **S10. `SSH_FXP_RENAME` and `posix-rename@openssh.com` share one
  handler** but have opposite contracts for an existing target (fail vs
  replace).  Fix: FXP_RENAME fails if the target exists; posix variant
  removes and retries on `EEXIST`.
- **S11. Package licensing.**  `RiscPkg/Copyright` holds only the MIT
  text; libssh (LGPL 2.1, statically linked: notice, licence text, relink
  means) and mbedTLS (Apache 2.0 LICENSE/NOTICE) and UnixLib's notice
  belong in it; `!Help` and Info should name the libraries' licences.
- **S12. EOF on a non-pty shell is ignored** (`tw_eof` is a no-op), so
  `ssh host < commands.txt` hangs after the input.  Fix: finish once
  pending input has been flushed.
- **S13. Supply chain.**  Tarballs fetched without checksums; Docker base
  image `:latest`.  Fix: SHA-256 pins in `tools/build-deps.sh`, image
  pinned by tag or digest.

## Low

- **S14.** `ro_load_file` sizes the buffer with OS_File 17 then loads with
  OS_File 255 unbounded; a file that grew in between overruns the heap.
  Load with OS_GBPB to the known length.
- **S15.** `tw_data` drops input beyond ~4 KB per SSH packet silently.
  Translate and queue in chunks.
- **S16.** `flush_pending` bursts up to 4 KB of Input messages; the
  module's input buffer size is unknown.  Verify with a 4 KB pipe.
- **S17.** The idle loop wakes every 2 cs even with no sessions; use a
  longer idle when `server_poll` reports none.
- **S18.** `info_values[II_COMPILER]` is initialised from `__VERSION__`
  into `char[96]`; a longer string would lose its terminator.  Fill it
  with `snprintf` at run time.
- **S19.** Keys window: DataLoad filename is assumed NUL-terminated (any
  control character is allowed); `Message_DataSave` (drag from an editor)
  is not handled.
- **S20.** `Maintainer:` in Control lacks an e-mail address.
- **S21.** `CMAKE_C_FLAGS` adds `-O2` but Release adds `-O3` after it.
- **S22.** No automated tests; `make test` needs a live emulator.
- **S23.** Memory headroom with 8 sessions is unmeasured; a fatal signal
  leaves TaskWindow children in the Task Manager.

# Third pass (same day): operations, desktop conventions, exec semantics

R1 to R8 were addressed in 9fab5d2, R9 to R14 in 3a5f3a5.  Both are built
and installed but not yet exercised on the emulator: the exec exit status,
stderr split, Options file, log file, Verbose tick and second-launch box
still need the restart-and-run check.

Angles: run-at-boot and administration, RISC OS Style Guide, what a Unix
user scripting `ssh` sees, log hygiene, packaging policy, build
portability.  Findings from my read and an independent reviewer, merged.

## High

- **R1. Exec sessions die on stdin EOF.**  `tw_eof` applies the "quiet for
  1 s after EOF" rule to exec channels too, so `ssh -n host cmd`, a
  redirected stdin, or any `ssh` inside a script (stdin not a tty: EOF is
  sent at once) finishes the channel and kills the child the first time
  the command is silent for a second.  Fix: for a child started with a
  command, finish only on Morio/TaskCloseDown; keep the quiet timer for
  the non-pty shell only.
- **R2. Boot-time error boxes.**  With the `Run` component flag PackMan
  starts `!SSHd` from the boot sequence, where the `Error` lines in `!Run`
  and the modal OK-only `Wimp_ReportError` in `fatal()` stop the rest of
  the boot until someone clicks.  Fix: drop the `Error` lines (the server
  reports missing CryptRandom itself), log fatal startup errors to the log
  file and show a non-blocking notice, or a box with Cancel.
- **R3. Settings only in `!Run`, which PackMan overwrites on upgrade.**  An
  admin's `-p`/`-r`/`-v` edits silently revert.  Fix: `!Run` runs
  `<Choices$Write>.SSHd.Options` (an Obey file setting `SSHd$Options`) if
  present and passes `<SSHd$Options>` to the server; document that a
  running instance keeps the old binary after an upgrade and must be quit
  and restarted (Info shows which version runs).

## Medium

- **R4. Exit status and quoted commands.**  Exec status is always 0 and
  commands containing `"` are refused, so a scripted loop cannot detect
  failure.  Fix with one mechanism: write the command to a scratch Obey
  file (`Set SSHd$Rc 1`, the command verbatim, `Set SSHd$Rc 0`), run
  `TaskWindow "Obey <file>" -quit`, read the variable on Morio (an error
  aborts the Obey file and leaves 1); this also lifts the quote and
  200-character limits.  Send refusals and errors on the channel's stderr
  so stdout stays clean.
- **R5. Terminal key translation in non-pty mode.**  In `ssh host cmd <
  file` a 0x04 byte ends the session, 0x03 becomes Escape and 0x08 DEL.
  Fix: translate control keys only when a pty was requested; otherwise
  only line ends.
- **R6. Log hygiene.**  User names, exec commands (logged before
  validation), subsystem names, key comments (including ones imported from
  another machine) and libssh error strings reach the log unsanitised.
  `Wimp_TextOp` stops at a control character, hiding the rest of the line,
  and in text mode the bytes go to the VDU.  Fix: replace bytes below 0x20
  and 0x7f with `?` in `vlog()` and in `auth_describe_one`.
- **R7. No persistent log.**  The ring dies with the task and the fatal
  RISC OS error from `on_oserror` is printed over the desktop.  Fix: append
  every line to `<Choices$Write>.SSHd.log` (truncated at start when over
  ~256 KB) and route `on_oserror` through it.
- **R8. `tools/find-rpcemu.sh` on Linux.**  GNU `stat -f %m` succeeds and
  prints the mount point, so the `stat -c` fallback never runs and the
  numeric comparison fails.  Fix: try `stat -c %Y` first.

## Low

- **R9. Log window usability.**  No horizontal scrollbar with a 1600-unit
  extent, so lines are cut at ~90 characters; and every new line scrolls
  to the bottom even while an admin reads older lines.  Fix: horizontal
  scrollbar and a wider extent; follow only when already at the bottom.
- **R10. Desktop conventions.**  The Keys window's right edge is off-screen
  at 640x480; Info should be a Style Guide submenu; `Message_HelpRequest`
  is not registered, so interactive help shows nothing;
  `Wimp_Initialise` claims version 310 while `Wimp_TextOp` needs 3.5.
- **R11. Launched twice.**  The second instance puts a second icon on the
  bar before `server_init` fails.  Fix: bind before `Wimp_Initialise`, or
  guard with an `SSHd$Running` variable in `!Run`.
- **R12. No `-b` bind address option; `-v` only by restart.**  Add `-b`
  and a "Verbose" tick on the menu.
- **R13. Package carries `RiscPkg/licences/*.txt` as well as the assembled
  Copyright.**  Copy only Control and the generated Copyright; consider
  `OSDepends: RISC OS (>= 5.00)`.
- **R14. CI `apt-get install` without `apt-get update`** can hit stale
  lists.

Checked and fine: Message_PreQuit (not needed for a server with no unsaved
data), binding INADDR_ANY before DHCP, sprites and !Boot, POSIX-sh scripts
and GNU-make-3.81 Makefile.
